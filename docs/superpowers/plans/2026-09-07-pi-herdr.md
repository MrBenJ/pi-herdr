# pi-herdr Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship independently installable, agent-callable pi tools for controlling the Herdr server hosting the current session, primarily using one new tab per worker agent.

**Architecture:** A synchronous extension factory registers four tools. Action-specific validation and pure argv builders feed an injected, streaming subprocess runner; operation-aware normalization returns bounded text and structured details, or throws a typed error. There is no orchestrator, direct socket client in production, or public programmatic execution API.

**Tech Stack:** TypeScript ESM; Node.js built-ins; pi 0.85.1; TypeBox 1.3.7; Vitest; Herdr CLI 0.8.2. Source TypeScript is loaded by pi's documented package loader without a production build.

**Spec:** `docs/superpowers/specs/2026-09-07-pi-herdr-design.md` — owner-approved 2026-09-07.

## Global Constraints

- V1 targets only the Herdr server hosting the current pi session, not multiple servers.
- V1 exposes agent-callable tools only; a direct programmatic API for Todos or other extensions is deferred.
- Require explicit targets for mutations; do not silently act on whichever workspace or pane happens to be focused.
- Creation and splitting default to explicit `--no-focus`.
- Every workspace, tab, or pane close requires an explicit target ID and `confirm: true`.
- Waits default to 30 seconds and allow a caller-supplied positive finite timeout up to 5 minutes.
- Default terminal reads to `visible`; callers may explicitly request recent history when needed. Output waits also default to the visible snapshot, with supported alternative sources available explicitly.
- Bound returned output at 2,000 lines or 50 KB, whichever is reached first.
- Never automatically retry non-idempotent operations after ambiguous failures.
- No layout or agent mutations on load, reload, or shutdown.
- Never automatically answer an agent's approval dialog.
- Do not modify `~/.pi/agent/extensions/herdr-agent-state.ts`.
- Do not publish, create a GitHub repository, or choose a license without the owner's approval.
- All spec non-goals apply: no Todos coupling, worktree lifecycle, worker pools, port allocation, model policy, or replacement lifecycle reporter.

## Frozen public tool input contract

Four flat object schemas avoid top-level union incompatibilities. `action` is required and uses `StringEnum`; fields are optional at schema level unless common to every action. Runtime validation inside `execute` enforces each action's required/allowed fields, even when called directly or after another extension mutates input. Reject unknown or action-inapplicable fields instead of ignoring them.

### Common field rules

| Field/type | Contract |
|---|---|
| `workspaceId`, `tabId`, `paneId` | Nonempty string without NUL, whitespace, or leading `-`; opaque ID, never derive or renumber it |
| `target` | Agent name or pane ID; same nonempty/no-NUL/no-whitespace/no-leading-`-` rule; Herdr resolves identity |
| `name` | Agent name matching `^[a-z][a-z0-9_-]{0,31}$`; uniqueness remains Herdr's responsibility |
| `cwd` | Nonempty string without NUL; passed literally, with no `@`, tilde, shell, or home expansion |
| `label`, `text`, `command`, `match`, `regex` | String without NUL; labels/commands/match/regex must be nonempty; text may be empty and remains literal |
| `args` | Array of strings without NUL, default `[]`; preserve empty items, spaces, quotes, newlines, and order |
| `keys` | Nonempty string array without NUL or empty items; Herdr validates key vocabulary atomically; document `esc` and `ctrl+c` |
| `env` | Array of `{ name: string, value: string }`, default `[]`; name matches `^[A-Za-z_][A-Za-z0-9_]*$`, value permits empty but no NUL; reject duplicate names and all `HERDR_*` names |
| `focus` | Boolean, default `false`; applicable only to create/split |
| `confirm` | Boolean at schema level; runtime must equal `true` for close |
| `timeoutMs` | Integer 1–300000, default 30000; only on startup, waits, and prompt with `wait: true` |
| `source` | Reads: `visible`, `recent`, `recent-unwrapped`, `detection`; output waits exclude `detection`; default `visible` |
| `lines` | Optional positive safe integer, capped at 1000000 to reject pathological requests; does not change returned-output limits |
| `format` | `text` or `ansi`, default `text`; only on reads |
| `raw` | Boolean, default `false`; only on pane output waits, preserving ANSI while matching |
| `until` | Nonempty array of `idle`, `working`, `blocked`, `done`, `unknown`; omit to use Herdr's settled-state defaults; reject duplicates |
| `ratio` | Optional finite number strictly between 0 and 1 |

The `HERDR_*` env restriction prevents consumers from retargeting launched worker context through launch options. Other supplied environment values are launch data, not overrides of the extension's own subprocess environment.

### Workspace and tab

| Tool/action | Required fields | Optional fields | CLI argv after executable |
|---|---|---|---|
| workspace/list | — | — | `workspace list` |
| workspace/inspect | workspaceId | — | `workspace get ID` |
| workspace/create | cwd | label, env, focus | `workspace create --cwd CWD [--label LABEL] [--env NAME=VALUE] --no-focus` |
| workspace/focus | workspaceId | — | `workspace focus ID` |
| workspace/close | workspaceId, confirm=true | — | `workspace close ID` |
| tab/list | — | workspaceId | `tab list [--workspace ID]` |
| tab/inspect | tabId | — | `tab get ID` |
| tab/create | workspaceId, cwd | label, env, focus | `tab create --workspace ID --cwd CWD [--label LABEL] [--env NAME=VALUE] --no-focus` |
| tab/rename | tabId, label | — | `tab rename ID LABEL` |
| tab/focus | tabId | — | `tab focus ID` |
| tab/close | tabId, confirm=true | — | `tab close ID` |

`workspace` above means the tool named `herdr_workspace`, and similarly for the other groups. Brackets denote omitted optional argv tokens, not literal brackets. Emit one `--env`, `NAME=VALUE` pair per entry. Emit `--focus` instead of `--no-focus` only for explicit `focus: true`. `cwd` is intentionally required for layout creation/splitting so the server does not silently choose a directory.

### Pane

| Action | Required fields | Optional fields | CLI argv after `pane` |
|---|---|---|---|
| list | — | workspaceId | `list [--workspace ID]` |
| inspect | paneId | — | `get ID` |
| split | paneId, cwd, direction | ratio, env, focus | `split --pane ID --direction DIRECTION [--ratio RATIO] --cwd CWD [--env NAME=VALUE] --no-focus` |
| run | paneId, command | — | `run ID COMMAND` |
| send-text | paneId, text | — | `send-text ID TEXT` |
| send-keys | paneId, keys | — | `send-keys ID KEY...` |
| read | paneId | source, lines, format | `read ID --source SOURCE [--lines N] --format FORMAT` |
| wait-output | paneId, exactly one of match/regex | source, lines, raw, timeoutMs | `wait-output ID --match TEXT --source SOURCE [--lines N] --timeout MS [--raw]` |
| focus-neighbor | paneId, direction | — | `focus --pane ID --direction DIRECTION` |
| close | paneId, confirm=true | — | `close ID` |

For split, direction is `right` or `down`; for focus-neighbor it is `left`, `right`, `up`, or `down`. Regex selection emits `--regex PATTERN` instead of `--match TEXT`. Do not compile Rust regexes with JavaScript RegExp; Herdr owns regex syntax validation. No `--current` or omitted source pane is emitted.

`run` passes one command string: it intentionally executes shell syntax in the remote terminal. It is not safe argv-based execution of the remote command.

### Agent

| Action | Required fields | Optional fields | CLI argv after `agent` |
|---|---|---|---|
| list | — | — | `list` |
| inspect | target | — | `get TARGET` |
| start | name, kind, paneId | args, timeoutMs | `start NAME --kind KIND --pane ID --timeout MS [-- ARG...]` |
| rename | target, exactly one of name/clear=true | — | `rename TARGET NAME` or `rename TARGET --clear` |
| prompt | target, text | wait, until, timeoutMs | `prompt TARGET TEXT [--wait [--until STATE] --timeout MS]` |
| send-keys | target, keys | — | `send-keys TARGET KEY...` |
| read | target | source, lines, format | `read TARGET --source SOURCE [--lines N] --format FORMAT` |
| wait | target | until, timeoutMs | `wait TARGET [--until STATE] --timeout MS` |
| focus | target | — | `focus TARGET` |

`wait` on prompt defaults to `false`; reject `until` or `timeoutMs` unless `wait: true`. Repeat `--until STATE` for each explicitly supplied state. Startup waits always have a finite timeout and emit the agent-argument separator only when `args.length > 0`.

Freeze kind enum to the 0.8.2 help list: `pi`, `claude`, `codex`, `gemini`, `cursor`, `devin`, `agy`, `cline`, `omp`, `mastracode`, `opencode`, `copilot`, `kimi`, `kiro`, `droid`, `amp`, `grok`, `hermes`, `kilo`, `qodercli`, `qwen`, `maki`. This means the CLI accepts those kinds, not that pi-herdr has integration-tested every executable/provider.

## Transport and result policy

1. `resolveHost(env)` requires `HERDR_ENV === "1"`, a nonempty absolute `HERDR_SOCKET_PATH`, and no NUL in that path. Preserve that path in a fresh child environment and delete `HERDR_SESSION`. Never call a session selector or search socket locations. Use executable `herdr` via PATH, matching the installed skill; no caller-supplied executable/server field.
2. Resolve context at tool invocation, not extension import. All validation happens before spawn. A pre-aborted signal returns a thrown cancellation without spawning or creating capture files.
3. Normal non-wait commands get a 30000 ms subprocess deadline. Wait/start/prompt-wait commands get the requested/default CLI timeout plus a 1000 ms response-drain allowance. Thus the largest subprocess deadline is 301000 ms; the largest requested Herdr wait is still 300000 ms.
4. `spawn(executable, argv, { shell: false, cwd, env, stdio: ["ignore", "pipe", "pipe"] })`. There is exactly one action invocation, with no retry loop. The CLI may perform its own read-only ping handshake; this is not a second action invocation.
5. On cancellation/deadline, terminate only the local CLI subprocess with SIGTERM, escalate to SIGKILL after 250 ms if necessary, await close, and clean timers/listeners. Do not signal the Herdr server, pane shell, or remote agent. Never send a remote close to implement cleanup.
6. Capture stdout and stderr separately under one `mkdtemp` directory with mode 0700 and files mode 0600. Stream to file with backpressure. Hold at most 51204 raw preview bytes per stream plus bounded stream chunks; decode through StringDecoder so multibyte characters are not split. Track total bytes/newlines incrementally.
7. Set the presentation limit to **51200 UTF-8 bytes and 2000 lines**, including a truncation notice. Use `truncateHead` on the bounded preview after reserving the actual notice length/line count. Empty output is zero lines; a trailing newline does not create an extra content line. Test boundary behavior explicitly rather than relying on a different library line-count convention.
8. Add a **64 MiB combined raw capture ceiling per call**. At the ceiling, stop capture and terminate the local CLI; throw `resource_limit`, mark artifacts `complete: false`, and describe them as partial captures, not full output. This is an emergency disk-safety failure, distinct from ordinary presentation truncation. No background artifact janitor starts on load.
9. Keep artifacts only when output was truncated, parsing failed, a call was interrupted, or diagnostics were omitted; delete small successful-call captures. Retained private artifacts survive reload/shutdown so returned paths remain usable; users/OS may remove them later. Document that they can contain sensitive terminal output and are not durable storage. Delete abandoned empty files/directories after pre-spawn failures.
10. Text reads preserve CLI text exactly when within limits; never JSON-parse a terminal read merely because it begins with `{`. Only pane/agent `read` use text mode. Output waits use JSON, including the matching snapshot and state metadata.
11. For JSON responses, parse only when the captured stream is complete and at most **1 MiB**. Larger JSON gets `response_too_large` with an artifact path, not fake success. The 1 MiB parse ceiling bounds JSON memory independently of the 50 KiB presentation ceiling. Parse successful stdout as `{ id: string, result: object }`; errors are usually `{ id: string, error: { code: string, message: string } }` on stderr. Reject empty/wrong-type/malformed success envelopes.
12. Validate required creation handles: workspace-create requires `workspace.workspace_id`, `tab.tab_id`, `root_pane.pane_id`; tab-create requires the latter two; pane-split requires `pane.pane_id`; agent-start requires `agent.pane_id`. A missing handle is malformed output, never an opportunity to manufacture IDs.
13. Normalize successful JSON to a concise action summary plus bounded serialized result text, preserving state and IDs. Include structured `details.result` only if its serialized size fits 51200 bytes; otherwise omit it explicitly with `resultOmitted: true` and provide the raw artifact path. This prevents bypassing output bounds through details. Remove `result.argv` on start before sizing/formatting.
14. Failure priority: explicit local stop reason; spawn failure; structured Herdr error; nonzero exit; malformed success output. `ENOENT` maps to missing_executable; `server_not_running` maps to server_unavailable; Herdr `timeout` maps to timeout; other Herdr codes remain operation_failed with the original code. Exit 2 without structured JSON is invalid_input. Other nonzero exits remain operation_failed. Do not assert a missing server from an arbitrary English diagnostic.
15. Any ambiguous failure after spawning a mutation uses `remoteOutcome: "unknown"`. Validation/context/pre-spawn failures use not_attempted; read-only failures use not_applicable. Even agent_not_ready or agent_prompt_stalled must not claim the worker was rolled back.
16. Throw `HerdrToolError`, whose bounded message is JSON encoding of `Failure`, so pi sets its documented error flag and the model retains machine-readable classification. Do not rely on pi serializing custom Error properties into result details. Successful results carry structured details normally. Redact exact nonempty sensitive values from reflected Herdr messages; never echo the entire argv/env to explain a failure. Raw diagnostic artifacts remain private and explicitly opt-in to inspect.

The 1 MiB parser limit, 64 MiB emergency capture ceiling, required layout cwd, and optional-field restrictions are concrete implementation choices for **plan review**, not previously implemented capabilities.
